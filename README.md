# writing-style-skill（中文写作技能）

一个可初始化的中文社交短文写作 Skill（供助手读取的操作规则）。你可以让助手诊断原稿、根据资料写草稿、保存交接记录，再从已确认的定稿中逐步积累个人写法。

它是本地目录式工具，不是 OpenAI 官方插件，也不自带某位作者的人设。模板中的作者画像、读者画像和偏好账本需要你初始化；初始生效偏好为 0，附带的例子和考卷全部虚构。

## 能帮你做什么

普通“去 AI 味”主要删套话、改词句。这里还保留三件事：

- **保护原稿和事实**：先区分你的原稿、参考资料、喜欢的范文和混合素材。你的完整原稿默认只诊断，改写需要你提出。
- **记清谁改了什么**：助手每轮重写留记录，作者口述原话单独记录，减少把助手文字误当成作者风格的情况。
- **让偏好逐条可确认**：DNA（个人偏好账本，像逐条确认的写作习惯）可以经历候选、生效、休眠和淘汰。脚本只计算和提示，长期风格变化由作者确认。

它主要面向中文社交短文，不是事实核验器，也不能从几篇稿子复制你的经历、情绪或完整文风。助手只保存稿件，不替你发布。

## 从独立副本开始

需要 Python 3.10 及以上；脚本只用标准库，无需安装第三方包。还需要一个能够读取本地文件、执行 Python 命令的助手。Claude Code、Codex、Cursor 等只是可选使用环境，不代表官方集成或经过所有平台验证。

从 [公开仓库](https://github.com/chendafu2573/writing-style-skill) 下载独立副本，或克隆（把远程项目复制到本地）。将项目放在你能找到的位置，不要求放进某个固定的技能目录。

```bash
git clone https://github.com/chendafu2573/writing-style-skill.git  # 克隆 writing-style-skill（中文写作技能）
cd writing-style-skill  # 进入 writing-style-skill（中文写作技能）
```

在独立副本的根目录打开终端或助手，再给助手这段话：

```text
读取当前目录的 SKILL.md（助手规则），按 §0 的 full 模式清单加载。
如果尚未初始化，请先和我确认作者、读者、写作目标及样本来源。
不要把空偏好账本当作已经学会我的风格。
```

full（完整加载）要读取 8 个规则和画像文件；lite（精简加载）只读入口文件，必须报告“完整 DNA 未应用”，不做偏好学习和定稿存档。具体操作规则以 [SKILL.md（助手规则）](SKILL.md) 为准。

## 第一次初始化

1. 填写 [personal-profile.md（作者画像）](reference/personal-profile.md)：笔名或称呼、常写主题、真实经历边界，以及不希望存入的私人信息。无需填写真实姓名和账号。
2. 填写 [reader-profile.md（读者画像）](reference/reader-profile.md)：写给谁看、对方懂多少、你希望读者获得什么。
3. 和助手确认 [style-card.md（稳定风格）](reference/style-card.md)：表达目标、口语程度、改写边界。没确认的内容保留“待确认”，先用通用规则试写。
4. 提供你自己写的样本，并说明是否已发布、是否允许存档。别人写的范文可以作参考，助手生成稿也可保存，但二者不能直接算成你的风格证据。

没有样本也能写草稿，但助手应明确说“尚未个性化”。初始化不会自动制造偏好；[dna.md（偏好账本）](reference/dna.md) 从空账本开始，真实样本和你明确确认的长期指令才是后续依据。

这些文件会逐渐包含你的私人信息。公开自己的副本前，要检查画像、定稿、草稿、日志、备份和考试记录；忽略规则不等于已经脱敏。

## 写一篇稿子的流程

```text
说明素材来源
    ↓
确认场景与改写力度
    ↓
写草稿 → 记录每轮助手重写
    ↓
你自己发布，并确认全文定稿
    ↓
预览复盘表 → 你确认 → 存档与更新统计
```

可以这样开始：

```text
这是 B 类资料，不是我的原稿：
[粘贴素材]
帮我写一条中文短文。缺少我的经历时先问，不要编第一人称故事。
```

如果你给的是原稿，先说“只诊断”“轻改”或“重写”。“可以”“好多了”“写进去”可能只确认局部修改，不自动等于全文定稿。本工具的“定稿”表示文章已由你发布；助手会先展示复盘表，确认后才存档。

含价格、统计指标等动态事实的草稿，需要发布前回原始来源复核并记录核查时间。来源字段只说明填了来源，不能证明来源支持正文。

接手一篇没写完的稿子，可以查看交接记录：

```bash
python3 scripts/draft.py show  # draft.py（草稿交接）查看未定稿记录
```

助手的存档操作使用 [draft.example.json（初稿示例）](templates/draft.example.json) 和 [finalize-payload.example.json（定稿示例）](templates/finalize-payload.example.json)。输入文件放在系统临时目录；将示例占位内容换成这篇稿子的真实内容，空偏好时锚点列表保持为空。

定稿预览不写入样本和账本，可能创建用于协调写入的锁文件：

```bash
python3 scripts/finalize.py --payload /tmp/payload.json --dry-run  # finalize.py（定稿记账）预览 payload.json（定稿输入）
```

正式存档会新增样本、追加日志并更新统计，必须在你已发布、确认终稿与复盘后执行：

```bash
python3 scripts/finalize.py --payload /tmp/payload.json  # finalize.py（定稿记账）保存 payload.json（定稿输入）
```

## 偏好与盲选比较

新写法先作为候选积累合格证据；脚本达到门槛时提示作者是否启用。作者的明确长期指令也可以确认后直接记录为生效偏好，但需要补上适用边界和“不应改”的例子。任何新增、修改、状态变化都不能由助手默默决定。

可以只读查看状态：

```bash
python3 scripts/dna_update.py report  # dna_update.py（偏好维护）查看偏好与统计
python3 scripts/dna_update.py suggest  # dna_update.py（偏好维护）查看待确认提示
```

[evals（评测资料）](evals/) 里的 3 张虚构考卷只演示盲选（隐藏版本身份后选择）的过程。真正比较个人风格之前，应替换为作者确认的事实摘要，并建立有个人证据的偏好基准。空偏好之间的比较没有个性化意义，三题胜负也不能证明整体文风已经变好。

建立考场、洗牌、交卷和更新基准的步骤见 [SKILL.md（助手规则）](SKILL.md) §4.9。脚本保留一次考试的题目与顺序，并检查洗牌后文字是否被改动；盲测是否隔离仍取决于助手环境和执行纪律。

| [CONTRIBUTING.md（贡献说明）](CONTRIBUTING.md) | 测试、脱敏和问题复现要求 |

已定稿文章以日期、稳定文章编号和版本号保存。同一文章再改会保留旧版本，不覆盖原稿。

## 中断与恢复

遇到“未完成的定稿存档记录”提示时，先停止其他维护。恢复会覆盖日志记录的旧文件，并移除这次未完成的新文件；先保存当前完整副本，确认日志来自此目录中的可信操作，再执行恢复。恢复只接受当前技能根目录内的目标路径，会先检查全部路径再写入；指向旧目录的恢复记录、或经符号链接跳出当前根目录的路径会被拒绝，并保留记录。恢复记录仍须可信；损坏、被改过或来源不明的记录应人工检查，不能直接信任。

```bash
python3 scripts/finalize.py --recover  # finalize.py（定稿记账）按可信日志还原文件
```

恢复后重新预览、确认，再存档。这个机制只覆盖恢复记录里的写入，不保证任意崩溃、磁盘损坏或外部手工改动后都能无损恢复。若工具拒绝、超时或报错，不能仅凭助手说“完成”就当作已存档，应查看实际输出与账本。

## 如何验证

以下命令不访问网络、不使用真实账号；测试使用临时副本。测试与语法检查会生成少量缓存文件，不会给当前账本新增样本。审计只检查一致性，不核实文字事实或作者身份。

```bash
python3 -m unittest discover -s tests -q  # tests（离线测试）运行完整测试
python3 -m py_compile scripts/*.py  # scripts（维护脚本）检查 Python 语法
python3 scripts/audit_skill.py --root .  # audit_skill.py（账本审计）核对当前账本
```

有 Git（版本记录工具）的副本还可检查未提交差异的空白错误：

```bash
git diff --check  # 检查当前改动的空白错误
```

脚本测试通过，表示这些受测流程符合约定；不等于已证明文章好读、事实正确或像作者本人。各平台环境仍以实际运行结果为准。

## 已知边界

- 来源分类根据输入类型、已记录的助手稿和作者口述判断；遗漏某轮重写仍可能污染作者样本，脚本不能鉴定真实作者。
- 锚点句只做文字匹配，无法解释作者为什么保留这句话。“守住了”和“印证”仍需助手判断、作者确认。
- 通用规则和风格检查只是提示，不能把真实口语、重复、脏话或碎句一律磨平。
- 工具不会后台扫描、自动发布、自动改偏好状态，也无法保证换模型后文风不变。
- 模板场景偏向中文社交短文。新增场景、长文或其他语言需要另行验证，不宜直接承诺同样效果。
