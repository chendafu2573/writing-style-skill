# project-research.md（项目查证流程）

> 只在写某个项目时读：产品介绍、活动帖、项目分析。
> 这里只放查证步骤，不放写法；怎么写按风格卡和偏好账本。

## 1. 先列来源

- 作者给的简报、活动说明只当起点。
- 再查：官网或文档、项目自己的实时数据页（储备证明、TVL、用户数等页面）、对应的官方 X 公告。
- 每个来源记下链接和查看日期。打不开的（例如 X 需要登录）记为「未核对」，交稿时告诉作者。

## 2. 数字逐个对实时页面

- 简报里的数字、项目数、合作方，能在实时页面核对的都去核对，以实时页面为准，写明数据日期。
- 简报和实时数据对不上时，交稿时列给作者（例：简报写 7200 万美元、4 个项目，实时页是 5986 万美元、3 个项目），不在正文里自己挑一个。

## 3. 分三类写

- **官方说的**：写成「官方说……」；没点名的照实写「没点名」。
- **能查到的**：写具体名字、数字和日期。
- **查不到的**：写「没查到」，不推测成事实。只有名字、没有说明的产品或合作，不替它解释。

## 4. 问作者的经历

- 按 `SKILL.md` §3.1 第 0 步，最多问 2 个：用过什么、花了多少、得到什么。
- 作者给的数字放开头，作者原话用 `--author-line` 记录；作者没用过的部分照实写「还没试」。

## 5. 活动帖

- **动笔前先读活动规则**，列出格式要求：字数（X 普通账号一条 280 字符，中文约 140 字）、要不要 @ 项目账号、要不要标签、提交哪一条。规则里没写的问作者。
- @ 项目账号放在句子中间，不放推文开头：X 会把 @ 开头的推文当成回复，只有同时关注双方的人看得到。
- 在邀请链接旁标明这是活动、作者自己做过。
- 涉及装插件、签名、授权的，交稿时提醒作者是否加防钓鱼提示。
- 正文含会变的数字，按 `SKILL.md` §4.1 时效检查：发布前超过 24 小时要复核。

## 6. 交稿时附查证清单

列出：用到的来源和日期、对不上的数字、未核对的来源、查不到的说法、替作者写的立场句、活动格式要求是否满足。
