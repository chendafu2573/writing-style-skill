# 样本与来源政策

## 1. 来源类型

定稿的定义（= 用户已发布）见 `SKILL.md`（助手规则） §4.1；输入类型（A/B/C/D）怎么问见 `SKILL.md`（助手规则） §1。

`来源类型` 由 `finalize.py`（定稿记账） 自动推出，Agent 不手填：

| 情况 | 来源类型 | 风格资格 | 能当什么证据 |
|---|---|---|---|
| 有 Agent 初稿，终稿与助手最后一版相同，且各版均无作者口述句 | `agent_draft` | 否 | 只有锚点句的「用上了」 |
| 有 Agent 初稿，作者在助手最后一版上改过，或已记录作者口述句 | `user_revision` | 是 | 作者新增的句子和已记录的口述原话可以「印证」；助手任何一版已有的句子不能冒充作者证据 |
| 没有初稿，A 我写的 | `user_original` | 是 | 最可靠；1 篇印证就够候选建议生效 |
| 没有初稿，C 喜欢的范文 | `reference_text` | 否 | 不能印证；作者点名喜欢哪种写法时，才记为候选，来源写「范文」 |
| 没有初稿，D 混合 | `mixed` | 否 | 只有作者写的片段可以印证，不计入门槛 |

B 类资料必须由 Agent 发挥，所以一定有初稿。无法确认来源的历史资产统一标记为 `legacy_unclassified`，不参与 DNA 学习，也不能自动回滚；已确认来源但 `rejected` 或 `superseded` 的资产保留在账本中，不能继续学习。

每轮助手重写通过 `draft.py`（草稿交接）的 `revise` 追加保存；作者口述原话用 `--author-line` 记录。使用口述归属例外时，印证依据须包含在已记录的口述句中；作者在终稿新增、助手任何一版都没有的句子也可以印证。没有待定区编号、直接提供 `first_generated` 的旧输入路径保持原判定方式。

## 2. 样本优先级

```text
用户明确说“这是我写的/最终原稿”
    > 用户确认并保留的修改
    > 已发布的用户文章
    > Agent 初稿
    > 未确认草稿
```

Agent 初稿永远不能作为个人风格证据。

## 3. 用户原稿处理

见 `SKILL.md`（助手规则） §1.1。

## 4. 风格学习边界

- 一篇作者原稿只能让新写法成为候选，不能直接生效；生效要作者确认（`SKILL.md`（助手规则） §4.5）。
- 作者明确说「以后都这样写」时，按口头指令处理（`SKILL.md`（助手规则） §4.7）。
- 作者说「这版不像我/太 AI/我自己写得更好」，该 Agent 版本用 `reject_sample.py`（失败标记） 标记为失败，复盘作废。
- 作者改掉 Agent 按偏好写的句子，记为「被改回」，不算成功。

## 5. 版本边界

内容版本和风格样本不是一回事：

- 同一篇 Agent 稿的修改：使用 `v1 → v2`。
- 用户独立提供的原稿：作为独立 `user_original` 样本，不伪装成上一版的修订。
- 旧版本永不覆盖；失败版本保留但标记 `rejected`，不进入风格训练。

## 6. 历史资产

没有有效来源类型的旧资产视为 `legacy_unclassified`：

- 可以查阅事实和结构
- 不作为个人风格证据
- 不计入自动 DNA 演化
- 只有用户明确确认后，才可重新标注来源
